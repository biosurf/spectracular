# Spectracular v1.5 change record

Created 11 November 2026 from the local v1.4 project.

## Preserved review baseline

The private v1.4 development folder was restored to its state before this implementation task. All 69 files matched the reconstructed baseline byte for byte, including the 43 files checked by its original deployment manifest.

Baseline checksums and the complete development diff are retained in the private project. The [development changelog](CHANGELOG.md) records intent, validation and remaining work, including historical Shiny changes whose files are not part of this public release.

The original v1.4 and complete v1.5 development folders are preserved separately from this public standalone release.

## Scientific behavior

The primary objective remains the smallest achievable maximum pairwise weight. The secondary objective remains the smallest sum among panels attaining that maximum.

The following are unchanged:

- The technology-specific pairwise calculations, excitation filtering and instrument data.
- Sequential addition of all edges at each unique weight threshold.
- Mandatory candidates, prohibited pairs and distinct group/slot choices.
- Conventional detector eligibility and optimized detector assignments.
- Function signatures and the saved-settings semantics.
- The manuscript and public Shiny deployment.

When both objective values tie, the selected equally optimal panel or its ordering can differ from v1.4. Results remain deterministic for the same ordered inputs.

## Implementation changes

1. `find_k_cliques()` accepts an optional `limit`, preserving its exhaustive default. Optimizers request at most two witnesses at each threshold to distinguish a unique solution from a tie.
2. The new `minimum_sum_clique(edges, nodes, k)` performs exact secondary branch-and-bound on the complete graph at the minimax threshold. It retains original slot and assignment IDs and all cross-component costs.
3. A compact component representation accelerates suitable graphs. A direct weighted-clique search handles other graphs, including size-k subsets of larger cliques. Local-state and pair-table budgets choose the representation; they never approximate or truncate the solution search.
4. All three optimizers, the reference workflow and Shiny use this shared helper. The UI and scientific formulas were not redesigned.
5. The reference workflow is now `spectracular_v1.5.R`; active paths and tests point to the new folder. Historical changelog entries are preserved.

There is no lexicographic refinement, runtime cutoff or approximate secondary answer.

## Licensing and dependencies

`LICENSE` is byte-identical to v1.4. The new optimizer code uses standard R; no runtime dependency on igraph, lpSolve, Rcpp or another solver was introduced. The optional igraph benchmark was already present in v1.4. Deployment files are kept in the private project.

This records the technical changes; it does not change the project's licensing terms.

- Reference workflow optimization and plot builds passed in all three modes.

## Review and follow-up

Both mathematical objectives are unchanged. When preparing manuscript revisions, check any implementation wording that specifically says every tied panel is enumerated and scored.

Broader performance testing, especially for large constrained graphs, remains necessary. Exact search retains combinatorial worst cases. Existing package-build and plot-range warnings occurred in regression checks; no failing final checks remain.

## Public standalone release — 18 November 2026

The public copy contains the standalone workflow, unchanged backend functions, spectra and all 25 instrument tables, backend tests, and user/scientific documentation. The standalone script and optional benchmark use explicit paths from the repository root. The README explains local R usage and links to the hosted web app.

Shiny source, web assets, deployment files, Shiny-dependent tests, local histories and profiling output, and private review artifacts are excluded. The complete development folders and existing license are unchanged. This packaging step does not resolve the separate patent-grant review or third-party data redistribution terms.
